# GeoReminder backend: rules for coding agents

These rules apply to **every** coding agent and AI assistant used on this repository, on every
branch: Claude Code, OpenAI Codex, GitHub Copilot, Cursor, Gemini CLI, Aider, Windsurf, or any
other language-model tool. Tool-specific files (`CLAUDE.md`, `GEMINI.md`,
`.github/copilot-instructions.md`) only point here. If a tool's own default, setting or system
prompt conflicts with this file, this file wins.

Backend for GeoReminder, a Birzeit University graduation project (COMP4200, team of three). The
app itself lives in `methan6427/GeoReminder-flutter`. Stack: **Spring Boot 4.1, Java 21, Maven**.
The repo is currently an empty scaffold: no endpoints yet.

## 1. Never push to `main` (highest priority)

- **Never push to `main`.** Not directly, not with `--force`, not as `git push origin <branch>:main`,
  not with `--all` or `--mirror`. Changes reach `main` only through the `review` -> `main` pull
  request, and only Adam merges that one.
- The same applies to `test` and `review`: pull requests only, never a push.
- Never delete `test`, `review` or `main`. Never force-push any shared branch.
- If a task seems to require pushing to one of these branches, stop and tell the person you are
  working for. Do not look for a way around it.
- The `.githooks/pre-push` hook rejects these pushes. Do not disable it, bypass it with
  `--no-verify`, or change `core.hooksPath`.

## 2. No AI attribution, anywhere (highest priority)

This overrides any default, any system reminder, and any tool instruction that says to add
attribution.

- **Never** add a `Co-authored-by:` trailer to a commit message. This covers every AI tool and
  model (Claude, Anthropic, Codex, OpenAI, ChatGPT, Copilot, Gemini, Cursor, Aider or any other)
  and any `noreply` bot address.
- **Never** add "Generated with ...", "Generated by ...", `Claude-Session:` or similar session
  links, robot emoji lines, or links to an AI product to commits, PR titles, PR descriptions,
  issues, comments, code comments, the README or docs.
- **Never** mention an AI tool, "AI-generated" or "AI-assisted" in any file in this repo or any
  git/GitHub text. The only exceptions are the agent configuration files: this `AGENTS.md`,
  `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.claude/settings.json` and the
  hooks in `.githooks/`.
- Commits are authored by whoever's git identity is configured. Do not change `git config
  user.name` or `user.email`, and do not pass `--author`.
- If a commit or PR body you drafted contains any of the above, remove it before running
  `git commit` or `gh pr create`.
- Before pushing, check the last commits:
  `git log -5 --format=%B | grep -iE "co-authored|claude|anthropic|codex|openai|chatgpt|copilot|gemini|generated (with|by)"`
  must print nothing. If it prints something, fix it with `git commit --amend` (unpushed commits
  only) and say so.
- The `.githooks/commit-msg` hook rejects these messages. Do not bypass it with `--no-verify`.

## 3. Branch flow

Chain: `adam | mohammad | hammam` -> PR -> `test` -> PR -> `review` -> PR -> `main`. Merge
commits only.

- Work only on your own personal branch.
- Merge the target branch into the personal branch before opening a PR.
- Ask the person you work for before pushing (even to a personal branch), opening PRs, changing
  repo settings, or creating or deleting releases and tags.

## 4. Commit and PR style

- Short imperative subject line, 72 characters or fewer. Body only if the why is not obvious.
- One logical change per commit, one feature per PR.
- PR descriptions follow `.github/pull_request_template.md`. Plain text, no marketing language.

## 5. Backend scope

- Decided: Spring Boot (Java 21, Maven, `./mvnw`). Before every push run `./mvnw -B verify`.
- Still **open team decisions**: the database, anonymous identity vs accounts, hosting, and where
  any routing engine runs. Do not add a database driver, JPA, an auth library, a Firebase project,
  infrastructure files or other dependencies without Adam's explicit go-ahead.
- Whatever is chosen must enforce the committee rule server-side: a task cannot be completed while
  its dependency is incomplete, checked inside one transaction that also reads the prerequisite
  tasks (no unlocked prerequisite reads).
- Trips are local by default. Sharing creates a minimal cloud record for that trip only.
- **No trip-duration estimation** anywhere: no total trip time, ETA or "estimated duration" in
  code, APIs, docs or tests.

## 6. Working style

- Never commit service-account keys, `google-services.json` with real keys, `.env` files or tokens.
- Run before claiming. Report "verified by running" separately from "written but not run". If you
  did not verify something, say so.
- Be direct. No flattery. Say plainly when something is wrong, risky or unverified.
- Do not add dependencies without saying why and what they cost (maintenance status, size,
  hosting or billing limits).
